# Sleep pipeline

1. The planner checks dimension, daylight/thunder, danger, bed availability, operator request or sleep debt, and action cooldowns. It pathfinds to a free bed or uses one already in range. A server `sleep` event—not a command or LLM—starts consolidation.
2. Capture that Minecraft day's STM events. Score them by novelty, recency, intensity and valence; generate deterministic intentions, episode summaries, and local lessons from observed data.
3. Optionally ask local Ollama for a thematic reflection and the configured cloud endpoint for a bounded update. Requests run concurrently, under individual deadlines and a 12-second shared advice budget. Waking or danger cancels pending advice; a disconnect or death aborts the transaction entirely.
4. Soul Guard validates every proposal and checks drift, social references, locked values and supported intentions. Models can suggest no more than three labels and an optional memory focus. Cloud advice may also suggest small profile changes. A configured cloud advisor that fails or returns invalid advice forces a deterministic result; local-only deployments can use validated Ollama advice. No untrusted free text enters state or memories.
5. Apply validated changes to the latest state, retaining unrelated updates such as operator journal edits. Atomically save the sleep marker, updated state, STM snapshot, LTM entries, and default-enabled audit diff together in `soul.md`. The day marker prevents duplicate consolidation on the same night, even after restart.
6. At wake and once it is daytime, report the stored intentions with fixed natural-language templates. A multiplayer server can require other players to sleep before advancing time. The bot does not use server commands to skip time or change sleep voting. If normal bed hours expire without a wake event, it requests to leave the bed.

Default maximum deltas are `±0.02` per trait, `±0.05` per player trust, and `±0.01` for any unlocked value. Configuration can tighten these caps but cannot exceed them. `ALLOW_CORE_VALUE_CHANGE=true` unlocks **helpfulness only**; kindness and prudence stay locked. An over-limit proposal is rejected as a whole. In-limit deltas are clamped at the state bounds.

The cloud input consists of typed event categories with importance weights, counts, profile values, trust numbers with anonymous snapshot slots, and supported intentions. It excludes raw chat, gamer tags, dates/coordinates, server identifiers, and user-supplied goals. Cloud models see compact features of the session; enable this only if you accept that disclosure. Ollama dialogue is separate and does receive filtered text addressed to the bot at your configured Ollama endpoint.
