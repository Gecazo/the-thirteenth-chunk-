# Sleep pipeline

1. The planner checks dimension, daylight/thunder, danger, bed availability, nightly schedule, and action cooldowns. It pathfinds to a free bed or uses one already in range. A server `sleep` event—not a command or LLM—starts consolidation.
2. Capture still-buffered events since the previous review, up to the last seven Minecraft days. Score them by novelty, recency, intensity and valence; generate intentions and archive episodes under their original day. This catches up after missed nights without fabricating earlier history.
3. Ask local Ollama for a thematic reflection, evidence-based skill rules, and which verified notes to retain in the active journal. Candidates come from the day's observed episodes, the existing journal, and a few older archive entries. The optional cloud endpoint can propose a bounded profile update but cannot see or edit the journal or private preference notes. Requests run concurrently under a 12-second shared advice budget. The review can finish at dawn if the server skips the night before the model answers. Danger and operator stop cancel pending advice; a disconnect or death aborts the transaction entirely.
4. Soul Guard validates proposals and checks drift, social references, locked values and supported intentions. Local skill rules are limited to observed job types and must match the recorded outcomes. For example, `tree: nearest` requires a nearby success and a distant failure. A failed cloud response falls back to deterministic profile/intentions without discarding accepted local skill rules. Models cannot supply executable code or free-text rules.
5. Apply validated changes to the latest state, retaining unrelated updates such as operator journal edits. Atomically save the sleep marker, updated state, STM snapshot, LTM entries, and default-enabled audit diff together in `soul.md`. The day marker prevents duplicate consolidation on the same night, even after restart.
6. At wake and once it is daytime, report the stored intentions with fixed natural-language templates. A multiplayer server can require other players to sleep before advancing time. The bot does not use server commands to skip time or change sleep voting. If normal bed hours expire without a wake event, it requests to leave the bed.

Default maximum deltas are `±0.02` per trait, `±0.05` per player trust, and `±0.01` for any unlocked value. Configuration can tighten these caps but cannot exceed them. `ALLOW_CORE_VALUE_CHANGE=true` unlocks **helpfulness only**; kindness and prudence stay locked. An over-limit proposal is rejected as a whole. In-limit deltas are clamped at the state bounds.

The cloud input consists of typed event categories with importance weights, counts, profile values, trust numbers with anonymous snapshot slots, and supported intentions. It excludes raw chat, gamer tags, dates/coordinates, server identifiers, and user-supplied goals. Cloud models see compact features of the session; enable this only if you accept that disclosure. Ollama dialogue is separate and does receive filtered text addressed to the bot at your configured Ollama endpoint.
